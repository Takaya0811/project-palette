# Claude Fable 5.1 とは

## 位置づけ

Claude Fable 5.1 は Anthropic の**最も高性能な一般提供モデル**。最も要求の厳しい推論と、長時間にわたるエージェント作業のために作られている。

- モデルID: `claude-fable-5-1`
- Claude Fable 5 の後継。同じティア・同じ価格
- 兄弟モデルとして Claude Mythos 5.1 (`claude-mythos-5-1`, Project Glasswing) がある。能力・価格・API は同一

## スペック

| 項目 | 値 |
|---|---|
| コンテキストウィンドウ | 1M トークン（最大値がそのままデフォルト） |
| 最大出力 | 128K トークン |
| 入力価格 | $10.00 / 1M トークン |
| 出力価格 | $50.00 / 1M トークン |
| キャッシュ読み込み | $0.25 / 1M トークン |
| トークナイザ | Opus 4.8 / 4.7 と同一 |

Opus 5 は $5 / $25 なので、Fable 5.1 は**入出力ともに Opus の2倍**の価格。最高性能と引き換えのコストになる。

## いつ使うか

Fable 5.1 は**明示的に指名されたときだけ**使うモデル。通常のデフォルトは Opus 5 (`claude-opus-5`)。

向いているケース:
- 最高難度の推論が要る
- 長時間・長ホライズンのエージェント作業
- 正しさがコストより重要

向いていないケース:
- 日常的なコーディング・チャット・分類。Opus 5 や Sonnet 5 で十分
- コスト最適化が要件に入っている場合

## 特徴1: 思考が常時オン

Fable 5.1 は**推論（thinking）を常にオンで動かす**。`thinking` パラメータは省略するか `{type: "adaptive"}` を送る。

- `{type: "disabled"}` → 400 エラー
- `{type: "enabled", budget_tokens: N}` → 400 エラー

つまり「思考をオフにする」「思考の予算をトークン数で決める」という以前のやり方はどちらも使えない。

代わりに深さは `output_config.effort` で制御する。指定できるのは `low` / `medium` / `high` / `xhigh` / `max` の5段階。デフォルトは `high`。

- 日常的な作業は `low` / `medium` で十分なことが多い
- 正しさが最優先なら `max`
- 新しいモデルは低い effort でも旧モデルの高い effort を上回ることがある

## 特徴2: 生の思考過程は返らない

推論の生のテキストは**どの設定でも外に出ない**。返るのは通常の `thinking` ブロックで、表示は `thinking.display` で選ぶ。

| 設定 | 挙動 |
|---|---|
| `omitted`（デフォルト） | `thinking` の中身は空文字 |
| `summarized` | 読める要約が返る |
| `updates`（ベータ） | ツール呼び出しの合間の進捗メモが返る |

デフォルトが `omitted` なので、推論をユーザーに見せたい場合は `summarized` を明示的に指定する必要がある。指定しないと「長い沈黙のあとに答えが出る」UIになる。

なお表示設定に関わらず、思考は実行されるし課金もされる。

## 特徴3: 拒否（refusal）への対応が必要

安全性の分類器がリクエストを拒否することがある。このとき HTTP は 200 で返り、`stop_reason` が `refusal` になる。`content` を読む前に必ず `stop_reason` を確認する。

対策として**サーバーサイドのフォールバックをデフォルトで入れる**ことが推奨されている。

```
betas: ["server-side-fallback-2026-07-01"]
fallbacks: "default"
```

これで拒否のカテゴリに応じて自動的に別モデルへ回るため、モデルのリストを自分で管理しなくてよい。拒否だけで出力が無い場合は課金されず、フォールバック側は自分のレートで課金される。

## 特徴4: Fable 5 からの3つの破壊的変更

Fable 5 のコードをそのまま持ってくると壊れる箇所が3つある。

1. **強制ツール利用が廃止**
   `tool_choice` の `any` / `tool` は 400 エラー。`auto` にしてプロンプトでツール名を指示するか、`strict: true` でスキーマを保証するか、JSON が欲しいだけなら構造化出力を使う。

2. **thinking ブロックがモデルに紐づく**
   生成したモデル以外に渡すと黙って破棄される（課金もされない）。

3. **preserved thinking（履歴編集の検査）**
   過去のターンを編集すると thinking ブロックが無効になる。ハーネスは**追記のみ**にする必要がある。2026-08-31 以降に作られたアカウントは編集済み履歴で 400 になる。

## その他の注意点

- **アシスタントのプレフィル不可**: 4.6 以降のファミリと同じ。400 エラーになる
- **30日のデータ保持が必須**: Anthropic の明示的な許可がない限り、ゼロデータ保持（ZDR）では使えない。条件を満たさない組織は 400 エラー
- **Priority Tier 非対応**: リクエストがバリデーションで失敗する
- **1ターンが長い**: 難しいタスクでは1リクエストが数分かかることがある。タイムアウト・ストリーミング・進捗表示の設計が要る
- **プロンプトの書き方が変わる**: 旧モデル向けに書かれた細かすぎるプロンプトは、かえって出力品質を下げる

## 新機能

- **メッセージ単位の effort 指定**（ベータ）: 会話の途中で effort を変えてもキャッシュが飛ばない
- **ターン限定のシステムメッセージ**（ベータ）: `clear_at: "next_user_message"` で1ターンだけ有効な指示を差し込める
- **進捗メモ** `thinking.display: "updates"`（ベータ）
- **コンテンツの来歴（provenance）**

## まとめ

Claude Fable 5.1 は「最高性能だが高価で、扱いに固有の作法があるモデル」。

- 常時思考オン、深さは `effort` で調整
- 拒否をハンドリングし、フォールバックを入れる
- 履歴は追記のみにする
- 通常は Opus 5 を使い、指名されたときだけ Fable 5.1 を使う
