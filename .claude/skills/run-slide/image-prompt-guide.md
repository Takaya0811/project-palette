# 画像プロンプト設計ガイド

Phase 1-4 で images.json を設計する際にこのファイルを読むこと。

## 基本方針

**画像は「見ただけで内容がわかる説明図」であること。**

- **情報量を多く** — シンプルすぎる画像はNG。日本語テキスト、アイコン、具体的なイラストで密度高く構成する
- **日本語テキスト必須** — タイトル、ラベル、箇条書きを画像内に入れる。Gemini は日本語テキスト描画が得意
- **具体的に描く** — 抽象的なノードやエッジではなく、実際の画面、ターミナル、UIモック等を描く
- **グラレコ風** — 手描き感のあるイラスト + 整理されたテキスト + アイコンの組み合わせ
- **プロンプトは日本語**で書く
- **プロバイダは `gemini`、サイズは `hor`** が基本

## モード別 構造化プロンプトテンプレート

**必ずいずれかのテンプレートに従う。**

### comparison（比較図）★最も使用頻度が高い

左右対比で2つの概念を比較。メリット・デメリット、具体的なイラスト付き。

```
{stylePrefix}

【構成】左右2分割の比較図。中央に対比ポイント。

【左側】{概念A}
- タイトル：「{概念A名}」（大きく表示）
- サブタイトル：{特徴を一言で}
- イラスト：{具体的な画面・モノのイラスト描写 — ターミナル画面、設定ファイル、UIスクショ等}
- メリット/特徴（箇条書き3-4点、日本語テキスト）

【右側】{概念B}
- タイトル：「{概念B名}」（大きく表示）
- サブタイトル：{特徴を一言で}
- イラスト：{具体的な画面・モノのイラスト描写}
- メリット/特徴（箇条書き3-4点、日本語テキスト）

【中央】対比を強調する視覚要素（矢印、VS表示、分割線等）

【スタイル】{テーマカラー指定}、日本語テキスト読みやすいサイズ、各要素にアイコン
```

### summary（まとめ図）

複数のポイントを1枚にまとめた俯瞰図。

```
{stylePrefix}

【中央】メインタイトル「{テーマ}」

【周囲に配置】{N}個のポイント
1. {ポイント1}（{具体的なアイコン/イラスト}）- {説明テキスト}
2. {ポイント2}（{具体的なアイコン/イラスト}）- {説明テキスト}
3. {ポイント3}（{具体的なアイコン/イラスト}）- {説明テキスト}

【視覚要素】中央から各ポイントへ線で接続、重要度に応じてサイズ変化

【スタイル】{テーマカラー指定}、日本語テキスト、各ポイントにアイコンを添える
```

### concept（概念の視覚化）

抽象概念を具体的なモノ・場面で表現する。

```
{stylePrefix}

【メインビジュアル】
{抽象概念}を{具体的なモノ/場面}として描く。

【構成要素】
- {要素1}：{具体的なイラスト描写} — ラベル「{日本語ラベル}」
- {要素2}：{具体的なイラスト描写} — ラベル「{日本語ラベル}」
- {要素3}：{具体的なイラスト描写} — ラベル「{日本語ラベル}」

【関係性】{矢印や線で要素間の関係を表現}

【テキスト要素】
- 各要素に日本語ラベルを表示
- 補足説明を小さいテキストで添える

【スタイル】{テーマカラー指定}、情報量を多く
```

### process（ステップ図）

手順やフローを視覚化。各ステップに具体的なイラストとラベル。

```
{stylePrefix}

【レイアウト】横方向に{N}ステップ、矢印で接続

【Step 1】{ステップ名}
- アイコン/イラスト：{具体的な描写}
- テキスト：「{日本語の説明}」
- 色：{テーマカラーの濃淡}

【Step 2】{ステップ名}
- アイコン/イラスト：{具体的な描写}
- テキスト：「{日本語の説明}」

（以下同様）

【スタイル】各ステップは角丸カード、番号表示、日本語ラベル
```

### anatomy（分解図・内部構造）

システムや概念の構成要素を分解して見せる。

```
{stylePrefix}

【メインビジュアル】
{システム/概念}の内部構造を分解して表示。

【構成要素】（上から下、または外から内へレイヤー表示）
1. {レイヤー1}（{具体的なイラスト}）- ラベル「{日本語}」- {役割説明}
2. {レイヤー2}（{具体的なイラスト}）- ラベル「{日本語}」- {役割説明}
3. {レイヤー3}（{具体的なイラスト}）- ラベル「{日本語}」- {役割説明}

【視覚表現】各レイヤーを層として重ね、点線で接続

【スタイル】{テーマカラー指定}、各レイヤーに日本語ラベル
```

### before-after（ビフォーアフター）

変化・改善を左右対比。具体的な状況描写が重要。

```
{stylePrefix}

【構成】左右分割、中央に大きな矢印で変化を強調

【左側 - Before】
- タイトル：「{導入前/改善前}」
- イラスト：{改善前の具体的な状況 — 散らかったデスク、エラー画面、手作業の様子等}
- 問題点（箇条書き3-4点、日本語）
- 😢 アイコン
- 色調：暗め・くすんだ色

【右側 - After】
- タイトル：「{導入後/改善後}」
- イラスト：{改善後の具体的な状況 — 整理されたUI、ダッシュボード、自動化の様子等}
- 改善点（箇条書き3-4点、日本語）
- 😊 アイコン
- 色調：明るい・鮮やかな色

【中央】大きな矢印、「{変化のキーワード}」テキスト

【スタイル】左右のコントラストを強調、日本語テキスト
```

### section-divider（セクション仕切り）

唯一の装飾的用途。テーマカラー必須だが自由記述可。

## 悪い例 vs 良い例

**NG — 抽象的、英語、情報がない:**
```
"prompt": "ダークUI風のベクター図解。背景色 #0d0d0d。ノードが4つ円形に配置。矢印で接続。テキストは入れない。"
```
→ 見ても何も伝わらない

**OK — 具体的、日本語テキスト入り、情報量が多い:**
```
"prompt": "説明画像、16:9。ダーク基調、エメラルドグリーンアクセント。\n\n【構成】左右2分割の比較図。\n\n【左側】従来のコード規約管理\n- タイトル：「CLAUDE.mdに全部書く」\n- イラスト：巨大なMarkdownファイルが画面からはみ出している。赤い波線（エラー）が多数\n- 問題点：「200個以上の指示」「遵守率が低下」「無関係な指示がノイズに」\n\n【右側】Progressive Disclosure\n- タイトル：「必要なときだけ参照」\n- イラスト：整理されたフォルダ構造。1つだけファイルが開いている\n- 利点：「最小限のルート指示」「タスク固有は別ファイル」「必要なときだけ読み込み」\n\n【中央】大きな矢印「→」\n\n【スタイル】高コントラスト、日本語テキスト読みやすく、各要素にアイコン"
```

## プロバイダ選択

全モード共通: **`gemini`**, **`hor`** を使う。
fal はセクション仕切りの雰囲気画像でのみ使用可。
