# スライド構成レビューチェックリスト

このチェックリストを使い、元ソース・スライドJSON・画像プロンプト一覧の3点を
**「このスライドでプレゼンして聴衆に刺さるか」** という編集者の目線で評価する。

問題があれば JSON / images.json を直接修正して保存すること。
修正不要なら「OK」とだけ返すこと。

---

## A. コンテンツ品質

- [ ] キーポイントが明確に絞り込まれているか（情報の羅列・ダンプになっていないか）
- [ ] 各スライドが「だから何？」に答えているか（So What テスト）
- [ ] 抽象的すぎないか、具体例・データ・引用で裏付けがあるか
- [ ] 元ソースの重要な主張・情報に抜け漏れがないか
- [ ] **定量チェック**: 元ソースの各セクション見出し(h2/h3)に対応するスライドが存在するか
- [ ] **N個宣言チェック**: 「4フェーズ」「3つの問題」「5選」等の数を宣言している場合、その数と同数の解説スライドが存在するか（概要テーブルに含まれるだけではNG、各項目に個別スライドが必要）
- [ ] **数値・引用チェック**: 元ソースに含まれる具体的な数値・統計・引用が、スライド内に反映されているか（重要な数値の脱落は致命的）

## B. ストーリー・演出

- [ ] 導入で聴衆の関心を掴めるか（問題提起・意外性・共感）
- [ ] 話の流れに論理的な必然性があるか（前のスライドが次の前提になっているか）
- [ ] クライマックス（最も伝えたいメッセージ）が明確で、適切な位置にあるか
- [ ] 結論が「次のアクション」や「持ち帰るべきこと」につながっているか
- [ ] テンポ: 情報過多で詰め込みすぎたスライドや、薄すぎるスライドがないか
- [ ] チープな印象を与えていないか（箇条書きの羅列だけ、テンプレ感、深みの欠如）

## C. スライド密度の設計

「1スライド=1メッセージ」は目安であり、硬いルールではない。
スライドの役割に応じて適切な密度を判断すること。

| 役割 | 望ましい密度 | 例 |
|------|------------|---|
| hook（導入） | リッチ可 | 問題提起+背景+数字を1枚の構図でまとめ、聴衆を引き込む |
| 概念説明 | リッチ可 | 複雑な概念を1枚絵（図解+補足テキスト）で視覚的に説明 |
| 要点・主張 | シンプル | 1つのメッセージを明確に打ち出す |
| まとめ | リッチ可 | 全体の要点を俯瞰できる1枚絵として構成 |
| セクション仕切り | シンプル | 画像+タイトルのみ |

- [ ] 各スライドの密度がその役割に対して適切か
- [ ] リッチなスライドは「1枚絵として成立」しているか（要素がバラバラに見えないか）
- [ ] シンプルなスライドが薄すぎて間延びしていないか

## D. ビジュアル戦略

### D-1. 画像パスの整合性（最重要）
- [ ] slide.json の image `src` が `./{name}-img-{id}.png` 形式か（`./output/` が入っていたらNG）
- [ ] images.json の `output` が `output/{name}-img-{id}.png` 形式か
- [ ] images.json の各 `slideIndex` が slide.json の実際のスライド番号と一致するか
- [ ] slide.json で参照されている全画像が images.json にも定義されているか（漏れなし）

### D-2. 画像の目的・有用性
- [ ] 各画像に明確な `mode` があるか（comparison / summary / concept / process / anatomy / before-after / section-divider）
- [ ] 画像がそのスライドの内容を視覚的に説明・補強しているか（装飾目的の無意味な画像はNG）
- [ ] 「この画像を見れば、テキストを読まなくてもセクションの要点がわかる」状態か
- [ ] 抽象概念にメタファー（具体物への置き換え）が使われているか

### D-3. プロンプト品質
- [ ] プロンプトが構造化テンプレート（【構成】【要素】【スタイル】）に従っているか（freeformはNG）
- [ ] `stylePrefix` がテーマのカラーパレット（hex値）を含んでいるか
- [ ] プロンプトが日本語で書かれているか（英語プロンプトはNG）
- [ ] 具体的な配置指示があるか（「左にA、右にB」等）
- [ ] `theme` フィールドが images.json に含まれ、選択テーマと一致しているか

### D-4. 構成・配置
- [ ] 画像スライドがJSON内に配置されているか（full-image / inline）
- [ ] 画像の配置バランス（偏りすぎ・少なすぎはないか）
- [ ] 全画像のビジュアルトーンが統一されているか（1枚だけ異質にならないか）
- [ ] inline画像の `position` が適切か（`right:XX%` / `left:XX%`）。containはレンダラーが自動付与するので不要。coverが必要な場合のみ明示

## E. 構造

- [ ] 情報の重複・冗長がないか
- [ ] スライド枚数が見積もりと大きく乖離していないか
- [ ] スライドの順序を入れ替えた方が流れが良くなる箇所はないか
