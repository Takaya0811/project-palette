# assign-slide-evaluator

スライドPDFの各ページを画像化して目視確認し、UI上の問題を検出・スコアリングし、修正指示をフィードバックファイルに書き出す。

**Prerequisites**: `pdftoppm` (`brew install poppler`) が PATH にあること。

**このスキルはJSONを直接修正しない。** 修正指示は feedback.md に書き出し、assign-slide-generator が修正を担当する。

## Input / Output

- **Input**: `$ARGUMENTS` = `output/{name}-slide.json [--range START-END]`
  - 入力JSONは `schema/slide-schema.json` 準拠
  - `--range`: 担当スライド範囲（1始まり）。省略時は全スライド
- **Output**:
  - 90点未満のスライドあり → `output/{name}-review-feedback.md`（修正指示）
  - 全スライド90点以上 → フィードバックファイルなし（合格報告のみ）

## 手順

### 0. 引数パース

`$ARGUMENTS` から JSONパスと `--range` を分離する。

```
例: "output/foo-slide.json --range 8-14"
→ INPUT = "output/foo-slide.json"
→ RANGE_START = 8, RANGE_END = 14
```

### 1. ビルド

**注意**: PDF/画像が既に存在する場合（呼び出し元が事前ビルド済み）はスキップしてよい。

```bash
BUILD_DIR=".claude/skills/run-slide/build-slide"
OUTDIR="$(dirname "$INPUT")"
BASENAME="$(basename "$INPUT" .json)"
PDF="${OUTDIR}/${BASENAME}.pdf"
MD="${OUTDIR}/${BASENAME}.md"

# PDFが存在しなければビルド
[ -f "$PDF" ] || node "${BUILD_DIR}/build.js" "$INPUT" "$PDF"
```

### 2. スライド画像を生成

**重要**: `marp --images png` は `bg right:XX%` 等の位置指定付き背景画像を描画しない。正確なレビューのため **PDF から画像を生成する（pdftoppm）**。

```bash
# 画像が既に存在しなければ PDF から生成
ls "${OUTDIR}/${BASENAME}".0*.png 2>/dev/null || \
  pdftoppm -png -r 150 "$PDF" "${OUTDIR}/${BASENAME}" && \
  cd "${OUTDIR}" && for f in ${BASENAME}-*.png; do
    # pdftoppm出力: {basename}-01.png → リネーム: {basename}.001.png
    num=$(echo "$f" | grep -oE '[0-9]+\.png$' | sed 's/\.png//')
    mv "$f" "${BASENAME}.$(printf '%03d' "$num").png"
  done && cd -
```

`{basename}.001.png`, `{basename}.002.png`, ... が生成される。

### 3. 各スライド画像を目視レビュー＆スコアリング

**`--range` が指定されている場合、その範囲のスライド画像のみ**を Read ツールで読み取る。
範囲指定なしなら全スライドを読み取る。

以下の観点で各スライドを **100点満点** でスコアリングする。

#### スコアリング基準（計100点）

| key | 観点 | 配点 | 満点 | 減点の目安 |
|-----|------|------|------|-----------|
| `overflow` | **はみ出し・オーバーフロー** | **25点** | テキスト・画像・テーブルがスライド領域内に完全に収まっている | テキストが右端/下端で切れている(-15)、画像がスライド外にはみ出し(-15)、テーブルの列が見切れ(-10)、箇条書きが下にはみ出し(-10) |
| `layout` | **レイアウト・余白** | **15点** | 余白バランスが良く、要素の配置が整っている | 上下左右の余白が不均等(-5)、要素間の間隔が詰まりすぎ(-10)、大きな空白(-5) |
| `readability` | **可読性** | **15点** | 文字サイズ・コントラストが最適で全テキストが読みやすい | フォントが小さすぎ(-10)、背景とのコントラスト不足(-5)、密集して読みにくい(-5) |
| `density` | **情報密度** | **15点** | スライドの役割に適切な情報量 | 詰め込みすぎ(-8)、スカスカで間延び(-8)、1スライドに複数メッセージ(-5) |
| `unity` | **視覚的統一感** | **10点** | テーマと調和し、スライド間でトーンが統一されている | テーマカラーから逸脱(-5)、フォントや配色がちぐはぐ(-5)、1枚だけ異質(-5) |
| `delivery` | **伝達力** | **20点** | メッセージが即座に伝わる | 何を伝えたいか不明確(-10)、テキストだけで視覚的補助なし(-5)、構成が論理的でない(-5) |

`key` 列は `eval-schema.json` の `breakdown_keys[].key` に対応。evaluator 出力 JSON では `breakdown.{key}.score` で各次元のスコアを返す。

**はみ出しは最重要**: テキストや画像がスライド端から切れている場合、そのスライドは自動的に60点以下とする。

### 4. フィードバック出力（90点未満のスライドがある場合）

**90点未満のスライド** がある場合、修正指示をフィードバックファイルに書き出す。

出力先: `output/{basename}-review-feedback.md`

#### フィードバックファイルの形式

```markdown
# Review Feedback

iteration: {N}
timestamp: {YYYY-MM-DDTHH:MM:SSZ}

## Summary

- 平均スコア: {X}点
- 不合格スライド: {カンマ区切りの番号}
- 合格スライド数: {N}/{total}

## Feedback

### Slide {番号} (score: {X}/100)

- **問題**: {具体的に何が問題か}
- **カテゴリ**: {はみ出し|レイアウト|可読性|情報密度|統一感|伝達力|レンダリング}
- **修正指示**: {slide-designerが実行すべき具体的な修正内容}
- **対象block**: {blocks配列の何番目か、またはスライド全体}

※ カテゴリ「レンダリング」= generatorのJSON修正では解消できないCSS/レンダラー起因の問題。修正指示には「レンダリング層の問題。generator修正不可」と明記すること。

### Slide {番号} (score: {X}/100)

...
```

#### 修正指示の大原則: はみ出したら分割。削除は絶対禁止

**「テキストを削除して」「項目を減らして」「コンテンツを減らす」は全て禁止。** はみ出しの正しい解決策は「器を広げる」こと — 1枚を2枚に分割するか、テキストを画像に変換する。

修正指示は以下の優先順位で書く:
1. **分割** — はみ出しているスライドを2枚に分ける。blocks の前半/後半を具体的に指定する
2. **画像化** — テキスト箇条書きを説明画像に変換（情報密度UP）
3. **再配置** — レイアウト調整（position変更、br挿入）
4. **圧縮** — 最終手段として文言を簡潔に（意味は削らない）

**自己チェック**: 修正指示を書いた後、「削除」「減らす」「除く」「なくす」という単語が含まれていないか確認せよ。含まれていたら分割指示に書き直す。

修正指示は **assign-slide-generator が機械的に実行できる粒度** で書く:

| 問題 | 良い修正指示 | 悪い修正指示 |
|------|------------|------------|
| テキストはみ出し | 「blocks[2-4]の箇条書きを summary 画像に変換」 | ~~「項目を3つに減らして」~~ |
| テキストはみ出し | 「このスライドを2枚に分割。blocks[0-2]を前半、blocks[3-5]を後半」 | ~~「テキストを削除して」~~ |
| 画像はみ出し | 「blocks[1]のposition を right:40% → right:30% に変更」 | 「画像を小さく」 |
| 詰め込みすぎ | 「テーブルを comparison 画像に変換し、補足テキストは次スライドに分割」 | ~~「行数を減らして」~~ |
| スカスカ | 「次のスライド(#{N+1})と統合」 | 「もっと内容を」 |

### 5. 完了報告

最終結果を以下のフォーマットで報告する。**スコアは必須**:

```
## スライドレビュー完了

- 入力: {input.json}
- フィードバック: {output/{basename}-review-feedback.md or "なし（全スライド合格）"}
- 最終スコア: 平均{X}点 (全スライド{最低点}点以上)

### スライド別スコア

| # | タイトル | スコア | 状態 |
|---|---------|--------|------|
| 1 | {title} | {score}/100 | {OK or "要修正: {概要}"} |
| 2 | {title} | {score}/100 | {OK or "要修正: {概要}"} |
| ...

### 不合格スライドの修正指示サマリ

- Slide {X}: {修正指示の要約}
- ...
```

## Gotchas

- **はみ出しの見落とし**: テキストが右端・下端でわずかに切れているケースを見逾しやすい。画像の端を注意深く確認する
- **はみ出し→分割が最優先**: テキストがはみ出している場合、「削除」「減らす」は絶対に書くな。「このスライドを2枚に分割。blocks[0-N]を前半、blocks[N+1-]を後半」と具体的に分割指示を書く。これが最も確実な修正
- **h2タイトル周辺の重なりはレンダリング問題の可能性**: h2はCSS `position: absolute` で配置されており、直後の要素に `h2 + *` で margin が付く仕組み。h2とコンテンツが重なっている場合、コンテンツ量の問題ではなくCSS/レンダラー起因の可能性がある。カテゴリ「レンダリング」で報告すること
- **右画像配置時のテキストはみ出し**: `image position: right:XX%` がある場合、左側テキスト領域は残りの幅に制約される。長い日本語テキストが折り返して下にはみ出す。この場合も分割が正解
